# M7 会话级教育评测规范

M7 新增独立的会话评测协议，不改 M6 单回合数据、评分器或产品流程。它能检查一次模型输出是否被完整带入后续回合，并为教师审阅教育判断保留独立记录。结构合法、证据引用合法、上下文连续、错因判断正确和追问有效分别计量，不能用其中一项代替另一项。

当前 `tests/evaluation/m7/math-candidates.inputs.json` 是作者原创的候选集。`AUTHOR_CREATED_PROVISIONAL`、`PROVISIONAL`、`AUTHOR_PROVISIONAL` 都表示尚未经教师审核；文件名、模板、Mock 结果和程序单测不构成教师金标，也不代表真实学生学习效果。正式质量结果默认是 `null`。

## 输入、标注与会话记录

输入 schema：`src/evaluation/conversation-schemas.ts`。数据集使用版本号、来源声明、case ID、题族 `familyId`、学科/学段、`DEBUG | BLIND`、审核状态和七种场景类型：`correct`、`calculation_error`、`conceptual_error`、`method_error`、`multiple_errors`、`insufficient_evidence`、`student_counterevidence`。题族不得跨调试与盲测分组。来源须逐题注明引用和许可；原创与成年知情同意来源分别声明，不把作者案例描述为真实学生样本。

模型实际接收的内容只有原产品 `DiagnosisContext`。`scenarioType`、标签、分组、审核状态和候选错因等元数据不传给模型。输入文件不允许夹带 `expected`、`gold` 或教师提示。标注独立保存在 sidecar；离线评分才读取 sidecar。

每例包含 `initialContext` 和按顺序排列的 `studentReplies: [{ id, content }]`。`conversationCaseInputHash` 对 `{ initialContext, studentReplies }` 作稳定 SHA-256；数据集另有整体 hash，涵盖版本、来源、分组和题目元数据。更改题目、学生步骤、回复文字或回复 ID 都要求重建相关绑定。不能靠重命名文件沿用旧审阅。

每个回合记录实际提交的完整 `context`、`contextHash`、回合下标、成功/失败、模型原始结构输出以及调用元数据。后续上下文由同一个确定规则生成，评分器独立重建并核对：

1. 保留所有题目、步骤和已有消息。
2. 将前次 `studentFacingText` 及未重复出现的 `followUpQuestion` 作为一条 `ASSISTANT` 消息，使用确定的 `conversationAssistantId`。
3. 将前次模型 `findings` 带入上下文，不能凭空清空或替换。
4. 使用脚本原有 ID 保存本轮学生回复为 `USER` 消息；历史学生回复的 ID 和文字保持不变。
5. 增加 `turnCount`、继承模型 `hintLevel`，下一回合的 `requestedAction` 为 `REPLY`。

即使有人重新计算了被篡改上下文的 hash，评分器也会通过独立重建发现历史不一致。证据作用域验证仍单独执行；一个 JSON 可以结构合法、引用合法，但上下文断链。

脚本容量为 `1 + studentReplies.length`，并受产品回合限制约束。合法的 `FINISH_REPORT` 或 `MARK_INCONCLUSIVE` 会立即结束会话，剩余回复计入 `notScheduledAfterTerminal`，不称为失败，也不继续向产品终态提交消息。任何终态后的额外记录都会被拒绝。尚未结束的会话缺回合、请求失败、非法输出或上下文断链均保留为失败。是否过早结束是教育语义问题，由教师量表审阅。

固定学生回复只用于可复现的离线流程。模型实际追问可能与脚本不衔接，教师必须据完整会话判断；不能将脚本顺利跑完解释为学生真正理解或迁移成功。

## 自动工程指标

以下指标出现在 `engineeringDiagnostics`，可以用于排查数据和软件问题，不声称教育准确率。

| 指标 | 检查范围 |
| --- | --- |
| `structureValidity` | 每个已调度回合是否符合输出 JSON schema |
| `evidenceScopeValidity` | 引用的步骤/学生回复/工具结果是否属于实际上下文，摘录是否来自原文，输出是否满足已有验证约束 |
| `contextContinuation` | 实际输入及其 hash 是否等于独立重建的上下文 |
| `finalStepSetExact/F1` | 最终引用步骤集合与 sidecar 允许集合的一致性；不判断错因语义 |
| `finalCategoriesAllowed` | 最终活跃发现的类别是否属于允许类别；非空允许类别要求至少一个活跃发现，空输出不会自动通过 |
| `abstentionProtocol` | 最终动作及发现状态是否满足 sidecar 的弃答协议要求；不判断弃答的教学适当性 |
| `counterevidenceCitation` | 是否引用了学生补充作为反证；不等于模型已正确修正判断 |

前 3 项按回合检查，再等权汇总到会话；其他自动指标每例计一次。缺输出按适用指标计 0；缺标签按 `null` 保留。每项同时输出 `denominator`、`missingCount`；同时查看 `reliability` 的会话/回合数与失败数。没有完整调用用量或定价时，token 和总费用保持 `null`，不视作免费或零 token。

## 教师教育量表

教师阅读原题、原始学生步骤、已实际发生的全部回合和证据；逐项按 0/1/2 填写，不能从类别字符串、答案关键词或规则命中自动推导。1 分表示部分达到、仍有影响判断的缺漏；2 分表示依据本题会话充分达到；0 分表示出现明确违背或未达到目标。没有适用内容或未完成审阅时填 `null`，并在 `rationale` 引用具体回合、步骤或学生回复。

| 人工指标 | 0 分锚点 | 2 分锚点 |
| --- | --- | --- |
| `trueWrongStepIdentification` 真正错步 | 将正确步骤说成错误、遗漏关键错误，或把证据不足说成确定错步 | 在教师允许的多种定位中准确区分已证实错误、正确步骤与尚不能判断的步骤；正确案例不硬造错误 |
| `factHypothesisSeparation` 事实与猜测 | 从一次作答直接断言概念缺陷、长期能力或未观察到的行为 | 明确区分可观察事实和待验证原因，结论力度与证据相称 |
| `followUpEffectiveness` 追问有效性 | 问题重复、暗示答案、与原因无关，或无法区分候选原因 | 一个主要问题能区分关键假设，并利用实际回答推进判断；须在会话中实际出现 `ASK_ONE_QUESTION` 才适用 |
| `counterevidenceCorrection` 反证纠正 | 忽略、歪曲学生的有效补充，继续坚持已被反驳的原因 | 正确认出反证并撤回/降低原假设，保留仍有依据的观察，不把一次修正当长期掌握 |
| `noPrematureAnswerLeakage` 不提前泄答案 | 未经允许或不必要地给出完整解法/答案，使追问失去判别价值 | 以必要局部信息支持诊断，保持学生独立作答机会 |
| `appropriateAbstention` 信息不足与弃答 | 信息不够仍编造错因；或有充分证据仍无理由回避 | 在题意/步骤/证据不足时说明边界，合理请求补充或弃答；证据够时给出有边界判断 |
| `suggestionSpecificity` 建议针对性 | 只说“多练”“认真”，或建议与观察无关 | 建议对应本次证据与尚待区分的原因，给出能核查独立表现的具体下一步 |

`trueWrongStepIdSets`、类别、弃答要求、反证要求、不泄答案要求与 `teacherNotes` 是人工金标 sidecar。空集合 `[[]]` 可表示允许结论为没有错步；`null` 表示未标注，二者不能混用。反证评分仅在金标要求反证修正时适用，不泄答案评分仅在金标明确要求时适用，弃答评分需要明确的真假标注。教师仍需审阅语义，程序不会用格式检查冒充教育判断。

人工分数在报告中除以 2 归一化到 0–1，不设未经验证的质量达标线。已知适用教师目标遇到执行失败按 0 纳入分母；成功输出缺人工评分、缺金标或未签收时保持 `null`。这使失败不会因缺评而消失，也不会把未完成的标注变成教学评分。应同时报告覆盖率，不能只报告已审少量成功案例的均值。

## 双教师与仲裁流程

1. 冻结输入版本、整体 hash 和题族分组。保留当前候选版本，不覆盖既有文件。`BLIND` 不用于调 prompt；审计读取或模拟过的会话标记为审计用途，不能成为该次最终质量结果。
2. 用 `prepare-teacher` 生成两个独立的空白标注模板和原始输入包。输入包不带作者 provisional 标签、场景错因分类或另一位教师意见。两位教师独立填写允许的等价定位、类别、弃答/反证/不泄答案要求及理由；占位文字和 `null` 不是已审核金标。
3. 教师意见一致时合并最终 `expected`；双方签收最终 **`{ caseId, inputHash, expected }`** 的 `hashValue`，分别记录 `reviewerId` 与真实 `reviewedAt`，状态为 `AGREED`。`independentReviews` 必须恰好两人且身份不同。签名不能仅绑定 `expected`。
4. 如意见不一致，保留双方独立意见对应的 hash；由独立的第三人给出有理由的最终裁决，`ADJUDICATED` 的 `adjudication.labelHash` 签收同一最终 payload。仲裁人不得与任一原审阅人相同。复用 M6 `isApprovedReview` 判断签收完整性。
5. 只有真实完成审核后，才新建经审核数据版本，将原创来源声明为 `AUTHOR_CREATED_TEACHER_REVIEWED` 或保留有真实依据的 `CONSENTED_ADULT`，相应 case 标记 `TEACHER_REVIEWED`、金标标记 `TEACHER_REVIEWED`。不能把原创题改称成年真实学生来源以绕过 gate。
6. 对模型输出另用 `prepare-output-reviews` 生成空白 A/B 量表和完整 transcript 包。输出包保留失败尝试，隐藏模型/供应商名称。两位教师独立评分，发生分歧时按相同第三人流程仲裁。
7. 输出评分的最终签收 payload 是 **`{ caseId, inputHash, transcriptHash, ratings }`**。`transcriptHash` 对导出的 `conversationTranscriptProjection` 作 hash，包含该例每一回合的 `turnIndex`、完整实际 `context`、`contextHash`、成功/失败状态与原始 `output` 或 `errorCode`。更改早期回合，即使最终文本未改，旧审阅也失效。这里的完整会话指全部教学对话，不含调用账单；教师包使用同一投影，屏蔽 `invocation` 内的供应商费用来源、token 和延迟等信息。调用用量/费用在原始 run 中独立审计，修改账单元数据不会改变教育签收 hash。

代码校验不同审阅者标识、hash 和仲裁流程，不认证现实身份。真实教师资格、知情同意和签收凭证应由项目负责人另行核实与保管；不要把模板中的 ID 换个名字就声称已有教师审阅。成年知情同意材料应有可核验的来源引用，不将个人身份材料写入仓库。

正式 `formalQuality` 只接受同时满足下列条件的 cohort：真实 `LIVE_API` 记录；用途 `FINAL_EVALUATION`；数据集非 `AUTHOR_CREATED_PROVISIONAL`；case 为 `BLIND` 和 `TEACHER_REVIEWED`；金标完成独立双审/仲裁；成功输出的人工评分也完成独立双审/仲裁且绑定输入和完整会话。成功输出缺审阅时相应质量项是 `null`，失败保留在适用分母。`SIMULATED`、`BLIND_AUDIT`、`DEBUG`、provisional 版本及未经审核标签都不能变成正式质量统计。

## 离线命令

入口 `scripts/eval/conversation.ts` 的六个命令均不调用付费 API。`simulate` 只显式构造 `MockGateway`，不读取 live 网关选择、密钥或 `AI_MODE`，不提供 `--execute` 功能。真实单条测试走另行授权的受控协议；后续真实批量会话需要新的授权。

```powershell
npx tsx scripts/eval/conversation.ts validate tests/evaluation/m7/math-candidates.inputs.json tests/evaluation/m7/math-candidates.annotations.provisional.json
npx tsx scripts/eval/conversation.ts plan tests/evaluation/m7/math-candidates.inputs.json
npx tsx scripts/eval/conversation.ts simulate tests/evaluation/m7/math-candidates.inputs.json
npx tsx scripts/eval/conversation.ts score <inputs.json> <run.json> [annotations.json] [output-reviews.json]
npx tsx scripts/eval/conversation.ts prepare-teacher tests/evaluation/m7/math-candidates.inputs.json
npx tsx scripts/eval/conversation.ts prepare-output-reviews <inputs.json> <run.json>
```

默认仅选择 `DEBUG`。`plan` / `simulate` 可用 `--cases id1,id2` 或 `--split DEBUG|BLIND|ALL`；显式 case 选择优先于 split。`simulate --split BLIND` 默认阻止。只有明确的数据/工具审计才能使用 `--audit-blind "具体审计理由"`；结果永久记录 `BLIND_AUDIT`，该用途不能计入最终质量。日常调试不要运行盲测模拟。`prepare-teacher` 与 `prepare-output-reviews` 不读取 provisional 标注文件。

每次命令在 `.local/m7-conversation/<命令>-<时间>-<UUID>/` 新建输出目录。所有文件使用独占创建；模拟还逐次保存不可覆盖的 checkpoint。旧验收文件保留，命令不删除文件，不安装浏览器，不清库。Mock 的网络请求数和供应商 API 费用为 0，调用记录注明费用依据；该数值不含 CPU 等本地运行成本。其 token 用量未知。真实 API 用量或定价缺失时费用仍为 `null`，不能由 Mock 的零费用规则推断。

当前 Mock 只支持原 M6 的少量内置示例。新数学候选大部分会首轮 `MARK_INCONCLUSIVE`，所以一次模拟的合法终态和较少调用数只能证明管线能运行。需要真实模型及教师审核后，才能知道多轮追问是否有效；手工构造三回合单测只验证上下文延续协议。

## 验证

`tests/unit/conversation-score.test.ts` 用纯内存 fixture 验证上下文篡改、持久回复 ID、缺失/失败分母、终态截断、终态后记录拒绝、类别空集合、结构与作用域分离、完整会话审阅绑定、独立双审/第三人仲裁、缺标空值和正式 cohort 的各个 gate。测试中的教师签名与 `LIVE_API` 标签均为评分器 fixture，不触发供应商调用，不是现实金标。

```powershell
npx vitest run tests/unit/conversation-score.test.ts
npx tsc --noEmit --incremental false
npx eslint src/evaluation/conversation-schemas.ts src/evaluation/conversation-score.ts scripts/eval/conversation.ts tests/unit/conversation-score.test.ts
```
