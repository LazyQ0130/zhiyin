# M9 教师试标说明

本次先做10例DEV材料可用性试标，目标是收集教师能否独立理解材料、证据在哪里有歧义、实际需要多少时间和精力。当前为 **PROVISIONAL / PENDING_HUMAN_REVIEW**。生成空表、校验通过、填写匿名ID或提供文件hash，均不表示实际教师已经审核、签收或签署；本次材料不是正式金标，不产生教育质量结论。

## 准备与分别分发

```powershell
npx tsx scripts/eval/m9-pilot.ts prepare
npx tsx scripts/eval/m9-pilot.ts validate .local/m9-pilot/prepare-实际UUID
```

每次命令都写入新的`.local/m9-pilot/<prepare或validate>-<UUID>/`，文件独占创建，验收目录也另建。历史文件和失败目录全部保留。命令只有prepare和validate，不提供签收、模型执行或正式冻结命令。

prepare生成`teacher-a/`和`teacher-b/`，每个目录均有`packet.md`、`packet.json`、`review.form.json`、`usability.form.json`和`checklist.md`。复用M8的`buildM8TeacherPackets`、`validateM8TeacherForm`生成和校验独立空表；两份包有不同packetId、绑定hash，教学输入完全相同。教师目录没有作者场景、题族、tags、参考答案、对方意见或预填签名。题目、步骤、相关预设回复原文、来源ID、顺序、文本hash和字符范围可读可查。预设回复显式标为`SCRIPTED_NOT_OBSERVED`，不是实际学生互动，也不是模型追问效果证据。

负责人只分别分发各自教师目录；根目录子输入、管理员manifest、交接文件含作者元数据，不能随教师包一并分发。实际访问隔离依赖负责人分别分发和控制存储权限，生成两个目录本身不能证明现实隔离或真实签收。

## 教师操作和可用性清单

先独立阅读说明、自行解题，再逐例用自己的话写`independentInterpretation`，并在`review.form.json`保留独立输入判断。可观察错误、候选原因和证据不足分别表述。原步骤正确时不硬造错误；原因、传播关系不清楚可以保持null或UNKNOWN。输入表没有模型教育评分；实际追问有效性、学生长期掌握及新版模型表现不能从本包判断。

`usability.form.json`全部实际人工字段初始为空或null：

- `completedIndependently`、`understoodInstructionsWithoutHelp`记录是否独立完成、能否无需协助理解说明；不能由程序默认true。
- 每例`independentInterpretation`及`observationEvidence`保存教师自己的解释与可定位观察；`usableWithoutClarification`记录能否无需补充说明使用材料。
- `ambiguousEvidence`记录证据歧义，true时必须写`ambiguityNotes`；已有原文用`ambiguityEvidence`定位，缺失的图或文字只解释缺失，不编造引用。
- 实际`actualStartedAt`、`actualFinishedAt`、`actualMinutes`、`actualEffort1To5`和逐例分钟/费力度由教师填写。1=很轻松，5=非常费力；程序不估算、不代填，不把命令耗时当教师耗时。
- 每例`dissentNotes`、`requestsThirdPartyReview`记录异议与是否请求第三人。`dissentRecordRef`、`thirdPartyArbitrationRef`只有在实际原件存在后填写私有引用；生成时均为null。

可用性表始终是`UNSIGNED_SELF_REPORT`，不会因非空或校验成功自动升级为已核验教师审核。真实身份、资质、联系方式及签署原件仅由负责人在私有目录管理，不进入Git。生成器不会创造教师、填真实签名或代教师审阅。

证据位置使用JavaScript **UTF-16** 下标，左闭右开`[start,end)`。例如原文`A😀中`长度为4：`A=[0,1)`、`😀=[1,3)`、`中=[3,4)`。它不是UTF-8字节、Unicode码点个数或屏幕字符位置。JSON转义解析后的换行算一个UTF-16单元；自动折行不改变原文。每个excerpt必须严格等于对应sourceId原文的`text.slice(start,end)`，不可用简写、改字或省略号代替。校验引文存在不等于判断语义成立。

## 返回、保留分歧和第三人仲裁

教师分别返回自己的目录。负责人保留收到的原文件、字节hash和接收记录，不覆盖A/B原意见，不用多数票或自动文字相似度抹平分歧。M9 validate只检查父/子来源、完整包绑定、覆盖、表结构及证据位置，输出`humanReviewsVerifiedByThisCommand=0`、`teacherIdentityOrSignatureVerified=false`、`formalQuality=null`。填写内容不作为自动核实现实身份的证据。

实际签署来源的接收、人工核验、原意见比较及独立第三人仲裁，沿用[M8 教师独立审核与指标](M8-教师独立审核与指标.md#原始签署来源与分歧)：`attach-source`→实际人工核实→`validate-audit`→`compare`。有分歧时使用`adjudicate`生成草稿，由不同于A/B的实际第三人填写理由、最终意见并签署，再保留第三原件与绑定。程序不代签、不自动宣称HUMAN_VERIFIED。当前M9 prepare/validate不执行这些真实收件或签收步骤。

试标收集后首先修订材料可理解性；任何修改另建版本并记录父子来源。之后如需正式金标、新真实模型调用或教育质量评测，须由负责人完成真实教师审核和相应下一阶段条件，不能把这10例的工程校验直接作正式质量结果。

## 通用填写说明（无案例答案）

负责人可将本小节单独提供给教师，不附本说明前面的作者选例表或管理员文件。不熟悉JSON的教师可直接在本人`packet.md`逐例空白处用中文写判断、理由和证据位置，在`checklist.md`勾选并补写独立完成情况、歧义、异议、实际时间和费力度；逐例信息注明caseId。管理员只能忠实转录到两份JSON表，不替教师推断、补结论或估算耗时。转录后的完整内容须由原教师逐项核对、确认并实际签收，才可将提交表与对应真实签署原件按M8的`attach-source`流程导入；导入后仍须人工核验来源，不能直接视为已审核。分别回传本人的完整原目录及实际原件，保留原文和转录版本；不自动填表、不模拟签名。

- `trueWrongStepIdSets`是“可接受的完整错误步骤集合”的备选列表：每个内层列表是一种完整组合，外层列表列出备选组合；只能使用本例已有步骤ID。`null`表示未知或未判断，`[[]]`表示明确无错误步骤，外层`[]`无效。多个备选不表示这些组合同时发生。
- `allowedCategories`可填写一个或多个不重复的粗类：`READING`=题意理解，`KNOWLEDGE`=概念与规则，`APPLICATION`=知识应用，`PLANNING`=解题规划，`EXECUTION`=运算与推理，`EXPRESSION`=表达与自检，`OTHER`=其他，`UNDETERMINED`=原因待确认。`null`是未判断；`UNDETERMINED`是教师已判断现有证据不足以确认原因。类别须有独立依据，不能仅凭算错确定原因。
- `requiresAbstention`表示是否需要说明证据不足并保留判断，`noErrorExpected`表示是否不应认定存在错误，`requiresCounterevidenceCorrection`表示是否需要根据有效反证修正判断，`forbidPrematureAnswer`表示是否要求避免过早泄露答案。各项`true`=是、`false`=否、`null`=未知、未审或不适用，原因写入`teacherNotes`；`false`不等于未填写。`teacherNotes`也保存教师解释及尚待核实之处。本输入包的`ratings`和`transcriptHash`保持`null`，不填模型输出评分或虚构会话。
- `rootCauseRelations`按步骤记录关系：`INITIAL`=初始错误，`PROPAGATED`=上游错误的传播，`INDEPENDENT`=另一个独立错误，`UNKNOWN`=关系未知。每项写`stepId`、候选根步骤`candidateRootStepId`（可为`null`）、上游步骤`upstreamStepIds`、理由`rationale`及证据`evidence`；未判断的整体保持`null`。填写关系项时须有可定位证据，不为凑项编造因果链。
- 证据均写`sourceId/start/end/excerpt`：`sourceId`取材料中已有ID，`[start,end)`按UTF-16下标，`excerpt`逐字等于该区间原文。原因未知、原文缺失或不适用时用文字说明，不造引用。身份、真实审阅时间、独立完成情况及签署只收实际教师的信息，未知项保留`null`或原空值。
