# M6 诊断评测与教师标注规范 v1.0

本规范建立可审计的评测流程。**当前没有教师金标或真实模型评测成绩**。已执行的六例是工程人员编写的合成演示，不能推出教育诊断准确率、学习提升或模型泛化能力。`tests/evaluation/teacher.annotations.template.json` 的空数组真实表示“尚未审核”。

## 三种证据须分别报告

| 类型 | 记录方式 | 可以证明 | 不能证明 |
| --- | --- | --- | --- |
| 模拟测试 | `run.mode=SIMULATED`，Mock / fetch fixture 明示 | 协议、评分器、业务边界和回归是否符合工程预期 | 百炼可用性、教师认可或教育准确率 |
| 真实 API 测试 | `LIVE_API`，受控授权后供应商真实返回、模型/提示词/usage/延迟/失败逐次保存 | 在指定时点、账户、地域和样本上的协议与输出情况 | 教师正确性；无教师标签仍 `teacherComparison=null` |
| 教师审核 | 独立标签 sidecar + 两位教师一致签收，或第三位仲裁；输出质量另审 | 针对固定输入与输出的人工判断 | 未覆盖人群/题型的结论或长期教学效果 |

评分程序不能验证签收人现实身份；`reviewerId`、时间和 hash 是流程声明及内容绑定，不是数字签名。实际试测负责人须离线保存教师资格、同意书和签收记录，避免将个人身份材料提交仓库。单测中 `teacher-a/b/c` 仅为测试 fixture，不代表真实教师。

## 文件隔离与版本

实现入口为 `src/evaluation/schemas.ts`、`score.ts`。三个文件职责不同：

1. `*.inputs.json`：严格输入 schema，包含 datasetId/version/provenance、caseId、来源许可和 `DiagnosisContext`。模型仅接收选定 case 的 `context`，不得接收 tags、来源描述、参考答案、gold 或教师评语。当前输入均 `SYNTHETIC`，不是未成年学生资料。
2. `*.annotations.json`：离线金标，绑定完整输入集 hash 与各 context hash。`ENGINEERING_PROVISIONAL` 为未教师认可的工程预期；`TEACHER_REVIEWED` 必须满足正式双审规则。
3. `run.json` 和 `output-reviews.json`：实际调用结果与后验人工评审分别保存，不能提前构造结果作为真实调用。run 显式列出 `caseIds`；少一条结果视为失败，多余/重复 ID 拒绝。输出评审还绑定 `outputHash`，输出变更后原评分失效。

所有 hash 使用 `hashValue` 的排序键 canonical JSON + SHA-256。添加题目、改步骤或标签后必须升版本并重新审核；hash 不匹配直接拒绝评分。副本文件可以保留原缩进，键顺序不影响 hash。输入 ID、步骤 ID、消息 ID 必须唯一，引用必须在当前题目上下文内。不得提交 `.env`、授权书、密钥、真实学生原文和运行记录；脚本结果统一创建 `.local/m6-evaluation/` 新目录，不覆盖历史证据。

## 教师标签制作

当前六例覆盖判别式符号、无步骤、正确过程、追问后反证、阅读边界、未知/题面注入弃答。只覆盖两个内置 Mock 场景及保守降级。正式数据集应另招募教师设计，按学科/题型/难度/错误层级/正确过程/信息不足/反证/开放题/噪声输入分层；每层记录样本数与来源许可，至少留出从未用于提示词调优的测试分区。不得将近重复题横跨开发与测试分区。测试集扩充前不能给出最低样本数已达到的声明或总体准确率。

1. 负责人给 A、B 两位学科教师独立分发输入与空白模板，隐藏模型输出、另一位标签及工程预期。先独立解决题目，确认题干充分、过程可读、唯一答案/多解边界。
2. 教师标注 `acceptableStepIdSets`（多个可接受的定位集合；无错误可用 `[[]]`，不适用用 null）、`acceptableCategorySets`（多个可接受的粗类集合，不适用 null）、`allowedActions`、`requiresAbstention`、`noErrorExpected`、`requiredEvidence` 及解释。`requiresAbstention=null` 表示本题不计此指标，false 表示不应弃答，true 表示应明确降级且不能给确定错因。初次差错不应直接断言心理原因。
3. 保留 A、B 各自完整原标签。最终标签的 `expected` 对象单独导出 JSON，通过 `label-hash` 计算 hash；各独立评审录入自己的 hash/时间/匿名 reviewerId。
4. 完全一致时 `review.status=AGREED` 且两人的 `labelHash` 都等于最终 `expected` hash。不同则第三位教师仲裁，`ADJUDICATED` 必须保留原两 hash、第三人最终 hash、时间与理由；第三人不能是 A/B。不能把一位教师的意见复制为两位审核。
5. 只有审核通过才将 `provenance` 改为 `TEACHER_REVIEWED`。缺审核、同名双审、签收后改标签，评分器均拒绝伪装成教师金标。初始金标空白时，教师比较保持 null。

粗类为 READING / KNOWLEDGE / APPLICATION / PLANNING / EXECUTION / EXPRESSION / OTHER / UNDETERMINED。多个原因无法从现有证据分辨时应允许假设或信息不足，不强迫选择唯一原因。原因语义与证据是否真正支持结论仍须人工评审，类别匹配只是粗类一致性。

## 输出人工盲审与 0–2 量表

输出后另生成两份空白评分包。教师分别阅读同一输入/输出和已定金标，隐藏供应商/模型名称、费用、延迟和另一位评分。对于追问，不仅核对“问号数量”：要判断是否能区分竞争假设，是否索取必要信息，是否泄漏答案、暗示长期能力判断或使学生被动复述。

| ratings 字段 | 0 分 | 1 分 | 2 分 | null 条件 |
| --- | --- | --- | --- | --- |
| reasonCorrectness | 错因错误、无证据确定归因，或忽略反证 | 大方向合理但未区分假设/措辞过强 | 与证据一致、区分观察和原因、正确保留不确定性 | 没有错因结论可审（如仅收集过程） |
| followUpEffectiveness | 无关、泄漏答案、多问题负担，或不能区分假设 | 有相关性但主要让学生复述，区分力有限 | 一个主要问题，针对关键步骤并能区分至少两种合理原因/补足必要信息 | 本轮无需追问（例如合理弃答/报告） |
| evidenceRelevance | 引用虽存在但不能支持结论/关键反证被忽略 | 部分相关，有证据遗漏或支撑过弱 | 支持/反证与陈述一致，范围及不确定性合理 | 没有证据结论可审 |

每项分值须解释。输出评分与标签相同地经双审一致或第三人仲裁，hash 对象为完整 `ratings`。评分程序将 0/1/2 归一为 0/0.5/1。null 不进入分母，不得填 2 代替不适用；非 ASK_ONE_QUESTION 回合填追问有效性分值会被拒绝。报告中的人工指标是**已审核输出的条件均值**，必须连同失败率、每项 denominator、已审输出覆盖率及各题型分层呈现。API 失败不能因“无输出可审”从总体成功率中消失。

## 指标定义与失败处理

| 指标 | 定义与限制 |
| --- | --- |
| stepExact / stepF1 | 引用步骤集合与可接受集合做最优匹配；多定位/漏定位降低 F1；不适用 null；不代表心理成因正确 |
| categoryExact / categoryF1 | 活跃发现的 category 集合匹配；REFUTED、UNRESOLVED 排除；只是类别一致性 |
| allowedAction | 行动是否在人工允许范围；不等于问句有效 |
| evidenceIntegrity | 正式 schema、引用存在、excerpt 是原文子串、初轮不能假装 VERIFIED 等全部校验通过；不能自动判断证据语义支持 |
| requiredEvidenceRecall | 关键来源引用覆盖；来源来自题干/步骤/学生回答/确定性规则，未知 gold 引用拒绝 |
| abstention | 应降级时仅允许 MARK_INCONCLUSIVE / REQUEST_INPUT_CORRECTION 且不得 SUPPORTED/VERIFIED；不应降级的样本反向检查 |
| noFabricatedError | 无错误样本不能增加未被否定的错误发现；允许 UNDETERMINED |
| 人工三项 | 只有有效教师金标及针对确切输出的批准盲审才计分；其余 null，不能用关键词或模型自评代替 |
| 延迟 | 全部已记录调用（含失败）的 p50/p95/max 和已知/未知个数；6例不具统计稳定性，不外推生产延迟 |
| 费用 / usage | 已知 token 量与费率依据；未知为 null。部分费用独立展示；只要一项未知，总费用为 null。estimatedCostCny 不是供应商账单 |

每个指标附 value 和 denominator；零分母为 null。选中但缺失/失败/非法输出，适用自动指标计 0 并列出 errorCode。未标样本不计金标一致性，单列 unannotatedCount。工程标签只进入 engineeringMetrics；只有 LIVE_API + TEACHER_REVIEWED 才展示 teacherComparison。模拟跑教师标签也不生成真实模型教师质量报告。失败结果不能静默切 Mock。

## 离线命令（不调用任何模型）

在仓库根目录运行：

```powershell
npx tsx scripts/eval/offline.ts validate tests/evaluation/engineering.inputs.json tests/evaluation/engineering.annotations.json
npx tsx scripts/eval/demo.ts
npx tsx scripts/eval/offline.ts prepare-teacher tests/evaluation/engineering.inputs.json
npx tsx scripts/eval/offline.ts label-hash <仅包含最终expected或ratings对象的.json文件>
npx tsx scripts/eval/offline.ts prepare-output-reviews tests/evaluation/engineering.inputs.json <本次run.json>
npx tsx scripts/eval/offline.ts score tests/evaluation/engineering.inputs.json <本次run.json> tests/evaluation/engineering.annotations.json
```

`score` 的第四个文件参数可传 `output-reviews.json`。尖括号是需替换的路径，不是 PowerShell 可直接执行内容。每次输出新目录；validate 失败或绑定失配退出 2，有模型失败的评分报告写出后退出 1。prepare-teacher 的默认 allowedActions 等值只是可解析的空白草稿，不是教师答案，review=DRAFT 且不可当金标。

真实 API 受控入口由 `scripts/eval/controlled.ts` 提供，须独立授权、限样本、限调用次数、限费用/输入输出；不在本规范中隐式授权。已有 `scripts/eval/run.ts` 的旧八例仍是工程回归；新评测程序不替代已有完整业务闭环与 Mock。
