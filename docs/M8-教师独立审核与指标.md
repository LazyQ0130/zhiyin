# M8 教师独立审核与指标

本流程补充教师审核材料和八项独立教育语义量表，不改写 M7 数据。固定输入版本为 `2026-10-23.2`，`datasetHash=241f0a5821f7310d5a8073a48af83af31d8fb9b0369a23875a6e59c35a6b707e`。DEV24 仍使用 M7 的 `DEBUG` 值，BLIND16 的案例、题族、输入、作者 provisional 标签及 manifest 保持原样。全部仍为 `PROVISIONAL`，实际教师审核数为 0。生成审核包和执行工程测试不改变这一事实。

## 独立审核包

运行下列离线命令会在新的 `.local/m8-teacher/<command>-<UUID>/` 写入材料，已有目录保留，文件独占创建。命令不导入模型网关，不调用供应商，不删除文件。

```powershell
npx tsx scripts/eval/m8-teacher.ts prepare
npx tsx scripts/eval/m8-teacher.ts prepare tests/evaluation/m7/math-candidates.inputs.json path/to/recorded-run.json
```

第一个命令生成输入金标表。第二个命令只包装已经录制的会话，不重放、不模拟、不向模型发送 BLIND。输出包保留完整原始会话投影及原始模型结构，不以新规则重新归一化旧输出。run/invocation 元数据中的模型名、供应商、费用及延迟不进入教师材料；原始教学文本保留，以便按完整会话核对。

`teacher-a/` 与 `teacher-b/` 各自包含 `packet.json`、`packet.md` 和 `review.form.json`。每位教师收到自己的目录，包内没有另一份意见或指向另一份意见的链接。两包的题目、步骤和预设回复相同，packet ID 独立。材料不含作者暂定金标、场景类别、题族、tags、参考答案或预填教育评分。管理员的分区清单位于审核目录根部，不分发给教师。

输入包中的预设学生回复明确为 `SCRIPTED_NOT_OBSERVED`，不能解释为已发生的学生行为。输出包只导出实际上下文中出现的学生消息，并区分 `ORIGINAL_INPUT` 与 `ACTUAL_TRANSCRIPT`；未发生的脚本回答不进入输出量表证据目录。完整 transcript 仍保留录制的上下文、成功/失败和原始输出，改动任何早期回合都会改变 transcriptHash。

每段证据有 source ID、原文、顺序和 `textHash=hashValue(text)`。人工填写的证据位置采用 JavaScript UTF-16 字符下标 `[start,end)`，excerpt 必须严格等于原文切片。程序检查位置与来源存在，不用“引用存在”推断教学语义正确。

输入金标保留 M7 的 `trueWrongStepIdSets`、`allowedCategories`、弃答/反证/答案泄漏要求与解释，并增加 `rootCauseRelations`。根因关系按步骤使用 `INITIAL | PROPAGATED | INDEPENDENT | UNKNOWN`；可填写候选根步骤、上游步骤、依据和原文位置。未审项为 null，不能为凑齐表格强判。根因关系的人工判断独立于运行时受限算术检查。

```powershell
npx tsx scripts/eval/m8-teacher.ts validate path/to/packet.json path/to/review.form.json
```

校验成功只表示结构、输入绑定和证据位置通过。教师匿名 ID、日期、hash 和非空 signature 字段都不能单独证明现实教师身份或真实签字。

## 原始签署来源与分歧

实际教师完成独立审阅后，将表设为 `SUBMITTED`，填写真实审阅时间和匿名标识。真实姓名、资格、联系方式、同意书和实际签署原件仅存私有目录，不提交 Git。生成器的 signature 字段始终为空；工具不创建教师身份、不代写真实签名、不把模板复制署成两人。

```powershell
npx tsx scripts/eval/m8-teacher.ts attach-source packet.json submitted.form.json actual-signed-source.pdf
npx tsx scripts/eval/m8-teacher.ts validate-audit source-audit.json original-signed-source.bin
npx tsx scripts/eval/m8-teacher.ts compare teacher-a.source-audit.json teacher-b.source-audit.json
```

导入保存完整 packet、完整原始表、表的 hash、实际来源文件字节 hash/长度和原件字节副本，状态仅为 `PENDING_HUMAN_AUDIT`。程序不将导入改成已审核。负责人需要人工核实实际教师、独立完成、真实签署、签署文件对应的完整表内容，再填写 humanAudit 的匿名核实人、时间、绑定 submissionHash、确认声明和具体说明，才可声明 `HUMAN_VERIFIED`。复核时必须同时运行 `validate-audit` 对照实际原件字节。此状态是人工声明；软件无法认证现实身份、签字真伪或资格。

比较输出保留 A/B 的完整逐例原标签及其不同 hash，不覆盖成最终标签。两人实际签署原件须分别保留，相同来源字节 hash 不能冒充两份独立原件。任何字段差异均列为分歧，包括解释文字差异；不会自动将不同含义归并为一致。存在分歧时需要第三位实际教师，身份不得为 A/B，并给出理由。

```powershell
npx tsx scripts/eval/m8-teacher.ts adjudicate audit-a.json audit-b.json case-id actual-third-pseudonym "实际分歧说明"
npx tsx scripts/eval/m8-teacher.ts attach-adjudication-source filled-adjudication.json actual-third-signed-source.pdf
npx tsx scripts/eval/m8-teacher.ts validate-decision decision.json actual-a-source actual-b-source actual-third-source
```

仲裁生成器仅给出 `DRAFT_ADJUDICATION`：A/B 原件完整保留，final、审阅时间及第三人签署来源为空。第三人需实际审阅并填写 final、理由和真实时间，再导入自己的原始签署文件，负责人独立核实其来源。仲裁 payload 绑定 caseId、inputHash、transcriptHash、审核类型、A/B 匿名标识/原表 hash/来源 hash/原标签 hash、最终表、第三人标识、理由和时间。不能仅签最终答案或把 A/B 原 hash 换成仲裁 hash。

只有 A/B 逐例内容完全一致且两份原始来源均已实际人工核实，`agree audit-a.json audit-b.json case-id` 才能生成 AGREED 决定。仲裁则由负责人实际完成来源核实后设置 `ADJUDICATED` 与对应 humanAudit 字段；程序不会自行完成这一人工步骤。`validate-decision` 核对实际 A/B/第三人来源字节和绑定，不代替人工核实。当前没有运行这些实际教师导入/签收操作，也没有真实签署来源。

## 八项独立人工教育量表

每项为 0/1/2/null，有值时必须给理由和准确证据位置。0 表示明确未达到；1 表示部分达到且有影响判断的缺漏；2 表示本次证据充分达到。null 表示未知、未审或不适用，需说明原因。禁止由类别词、关键词、schema 通过或数字答案自动填教育评分。

| 字段 | 人工审阅的问题 |
| --- | --- |
| observationLocation | 是否正确定位原始可观察错误，同时保留正确/不能判断的步骤？ |
| causalAttribution | 原因是否有区分性证据；是否从算错直接断言概念/读题缺陷？ |
| observationHypothesisSeparation | 观察、假设和仍待核实的内容是否明确区分？ |
| hintPollutionControl | 是否记录提示污染，避免把提示后答对当成独立掌握，并保留独立作答机会？ |
| rootCausePropagation | 是否区分初始错误、传播错误、独立错误与未知关系？ |
| counterevidenceCorrection | 是否理解有效反证并适度修正，避免轻信未经核实的抄写/录入自述？ |
| discriminativeQuestioning | 实际追问是否能区分关键假设，并根据实际回答推进判断？ |
| appropriateAbstention | 是否在证据不足时说明边界、请求补充或合理弃答？ |

输出量表与输入金标分开分发、独立填写和审核。反证无实际适用目标、没有发生追问、根因未标注等情况，相应分数保持 null。只给出两个匿名标识或将表的状态改名，不会产生教育评分。

```powershell
npx tsx scripts/eval/m8-teacher.ts score inputs.json recorded-run.json
npx tsx scripts/eval/m8-teacher.ts score inputs.json recorded-run.json gold-decisions.json output-decisions.json
```

`scoreM8Evaluation` 在新模块中调用 M7 工程检查，原始结构、证据作用域、上下文连续性及失败率位于 `engineeringDiagnostics` / `reliability`。八项 `teacherSemanticRubric` 只读取已实际人工核实来源、输入与完整会话绑定一致的人工决定，并将 0–2 除以 2。每项单独报告 value、denominator、missingCount。缺标签、未审、无适用目标及不能进行语义审阅的执行失败保持 null；执行失败率独立显示，不用工程失败自动编造教师语义分。

`formalQuality` 还要求 LIVE_API、FINAL_EVALUATION、经教师审核的新数据版本、BLIND 和逐例已审核状态。M7 冻结版保持 provisional，因此无论软件结构通过多少，当前 formalQuality 都为 null。少量已审输出的均值也不能推广为真实学生学习效果。原件 hash 是绑定与字节检查，不是密码学签名验证。
