# M9 有效性指标口径

本文件补充八类相互独立的有效性口径：七个会话级指标，以及帮助漏报/误报这一类的两个回合级指标。没有综合准确率。M8八项0/1/2教师量表和原有正式评测门禁保持不变；M9不从M8分数阈值、作者暂定标签、七类错因、关键词或确定性算术规则推导新的教育质量标签。

实现为`src/evaluation/m9-metrics.ts`、`m9-metrics-schemas.ts`；离线命令为`npx tsx scripts/eval/m9-metrics.ts`。程序不导入供应商网关，不调用模型。每次运行写入新UUID目录，独占创建文件，校验M7冻结文件前后hash，保留旧结果。

## 1. 每项分子、分母、适用性和来源

下表的“已审”均要求第3节完整来源链；仅填写表格或设置`HUMAN_VERIFIED`布尔/状态不算已审。`applicable`是单独的人工教育判断：`true`适用、`false`不适用、`null`未知；`outcome`仅在适用且能够判断时填`true/false`。已知适用性和结果都必须有理由及可定位原文证据。适用但结果不确定仍填`null`。

| 指标 | 单位 / 分母 | 分子 / 方向 | 人工依据及适用性边界 |
| --- | --- | --- | --- |
| 结论覆盖 `conclusionCoverage` | CASE：教师确认本次证据足以给出有边界结论、且输出结果已审的会话 | 给出了证据支持且覆盖主要现象的结论；越高越好 | 正确/无错结论也算结论；原因未知不等于所有现象均不可诊断。由本次原输入及实际互动判断能否诊断，不能由作者场景标签决定。 |
| 合理弃答 `reasonableAbstention` | CASE：教师确认本次证据不足，需要保留结论/归因、且结果已审的会话 | 系统适当保留结论，并说明边界或所需补充；越高越好 | `MARK_INCONCLUSIVE`仅是工程动作，不自动算合理。不能与“不合理弃答”合并一个得分。 |
| 不合理弃答 `unreasonableAbstention` | CASE：教师确认本次证据足以给出有边界结论、且结果已审的会话 | 无充分理由回避能够支持的结论；越低越好 | 适用范围与结论覆盖相同；程序拒绝同一份表内两个已知适用性相反。并非结论覆盖的强制补数，尚有其他未覆盖/错误结论的情形。 |
| 错误因果归因 `erroneousCausalAttribution` | CASE：教师确认实际输出提出至少一个原因归因、且能够审定的会话 | 至少一个归因缺证据或与证据矛盾；越低越好 | 观察到某步算错不自动等于提出心理/知识原因。先判断是否有归因，再判断证据；没有归因不算“归因正确”。这是会话发生率，不是逐个归因准确率。 |
| 帮助漏报 `hintMiss` | TURN：人工实际帮助等级>0、且被比较通道等级已知的回合 | 通道报0级；越低越好 | 人工读全部学生可见内容，不能抄模型`hintLevel`或内容规则。人工或通道未知均不填0。 |
| 帮助误报 `hintFalsePositive` | TURN：人工实际帮助等级=0、且被比较通道等级已知的回合 | 通道报>0级；越低越好 | 与漏报使用不同分母，不能用“全部回合”除二者，也不合成“提示正确率”。 |
| 重复根因 `duplicateRoots` | CASE：教师确认至少两个错误/发现需判断是否同源、且能够判断关系的会话 | 同一根因传播被重复计作独立根因；越低越好 | 由教师复核原步骤、实际输出和根因关系；不同类别或不同findingKey不自动代表独立根因；合并独立错误是另一种错误，仍由M8根因量表保留。 |
| 有效追问 `effectiveQuestioning` | CASE：确有已保存的追问及其后新增对应回答、且教师能够判断判别价值的会话 | 本次主要追问均能区分假设，并实际利用回答调整判断，无答案暗示/无效重复；越高越好 | 无追问/无对应已观察回答是结构排除，单列`structurallyExcludedCount`；不是教师给0分。原有USER消息、未发生的预设回答不能当本次追问回答。此处是会话级严格事件率，不是逐问题率。 |
| 有用下一步建议 `usefulNextStepAdvice` | CASE：工程完整且教师能够判断建议适当性的会话，包含合理弃答案例 | 给出与本次问题/证据缺口相符、可执行且不过早泄露答案的下一步；越高越好 | 应有建议却没有建议可编码为`false`，不能借“未输出”自动排除。只要求一次建议适当，不能声称学习保持/迁移。 |

帮助等级为0无帮助、1方向、2关键知识、3答案或局部结果。帮助比较分两个通道独立报告：

- `RECORDED_OUTPUT_DECLARATION`：保存会话中`hintLevel`字段。它可能已经过历史处理；没有上游原件时不能称为未经处理的供应商原始输出。
- `M8_GUARD_REPLAY`：对同一份已保存学生可见文本、追问及发现正文，离线运行当前M8内容复核。它是规则重放，没有产生另一份模型回答，也不是产品干预效果实验。复核无法判断时等级为`null`，不能据无匹配而称0级。

除二元漏报/误报，`hintLevelDifferences`另列等级低估（通道<人工）、高估（通道>人工）、完全相等三个诊断率及4×4计数表，分母均为人工和通道等级都已知的回合。人工2级、通道1级虽双方均有帮助，仍算等级低估。未知等级单列，不能以“双方均>0”宣称等级通过。

## 2. 缺失、失败、范围与工程描述

每项输出`value/numerator/denominator`。`denominator`只计适用且结果已知的实际已审单元；为0时`value=null`，不是0%或100%。同时列出：

- `candidateCount`：工程完整且满足结构机会的候选单元；有效追问只纳入实际有问有答的会话。
- `eligibleCount`、`eligibilityUnknownCount`、`outcomeUnknownCount`：已知适用数、适用性未知数、适用但结果未知数。
- `notApplicableCount`：有来源的人工不适用判断；结构排除单列，不混入此项。
- `missingCount`：适用性未知与适用但结果未知之和；`executionExcludedCount`另报工程失败，既不补质量0分也不伪造教师判断。
- `possibleEligibilityCount`：当前候选中适用数最小/最大范围；`pendingCompletionBounds`是在全部缺失项均适用这一有限集合补全假设下的最坏/最好范围。它不是置信区间、总体准确率或测得的教育效果。样本没有实际审核时出现[0,1]意味着当前完全无法识别质量。

报告另有`engineeringDescriptive`：终轮`FINISH_REPORT`发射率、非空finding发射率、`MARK_INCONCLUSIVE`发射率、INCONCLUSIVE finding数、保存追问数及操作失败率。分母和动作定义直接列出；它们不判断结论支持程度、弃答适当性或建议有效性。“报告发射0%”和“合理弃答率null”可以同时成立。

## 3. 补充表与真实来源链

`prepare inputs.json recorded-run.json`生成A/B分别独立的M9补充包、空表和规则。复用M8无作者标签的题目、步骤、实际会话source投影；每例绑定`caseId/inputHash/transcriptHash`，全包和口径另有hash。未观察的脚本回复不会放入输出审核包。原文证据采用UTF-16的`[start,end)`，程序核对准确文本；帮助编码至少引用对应回合MODEL_OUTPUT中实际学生可见内容。

新质量值必须同时具有：

1. M8输入金标与输出量表的有效人工审核决定；由原M8评分器重建source并验证，M8量表保持原样。
2. M9补充表A/B完整原始意见、两个不同审阅者和不同签署来源。A/B表的完整单例载荷相同才可一致；只要理由、证据或代码不同都保留分歧，交第三人。
3. M9来源复用M8实际签署文件hash/长度、人工核验者及时间、完整原始submissionHash绑定、实际教师及签署核实声明和核验说明。`attach-source`只附加字节并保持待人工核实，不自动认证教师。
4. 有分歧则须独立第三人的实际仲裁、理由、时间、不同签署来源及人工核实。仲裁payload hash绑定A/B原意见及来源、最终编码和第三人决定；改最终编码后须重新完成真实签署与绑定，不能覆盖原意见。
5. 评分时实际提供M8输入、M8输出、M9补充各A/B和适用第三人的来源文件字节；程序核对sha256和长度。不提供原件字节时，新质量值仍为null。

程序只能核对来源字节和声明绑定，不能认证现实教师身份、签名真伪或教育语义。负责人仍须现实核验，并将真实身份对应表和签署原件保存在私有受控目录。生成匿名ID、填写空表、单元测试使用的明确标注软件夹具都不增加实际教师数。A/B互盲还依赖分别分发及实际访问权限控制；生成两个目录不证明权限隔离已经落实。

CLI流程：

```text
prepare inputs.json recorded-run.json
validate supplemental.packet.json supplemental.form.json
attach-source packet.json submitted.form.json actual-signed-source
validate-audit supplemental.source-audit.json actual-signed-source
compare audit-a.json audit-b.json
agree human-audited-a.json human-audited-b.json caseId
adjudicate audit-a.json audit-b.json caseId actual-third-pseudonym reason
attach-adjudication-source filled-decision.json actual-third-signed-source
validate-decision decision.json actual-a-source actual-b-source [actual-third-source]
score inputs.json recorded-run.json [review-files.json]
```

`adjudicate`只产生未签署草稿；`attach-adjudication-source`只附加实际原件，保持待人工核实。负责人真实核验后才能填齐相应人工字段及完成状态；软件不能代签。`validate-audit/validate-decision`通过仅表示字节和绑定相符。

评分配置使用严格字段，路径相对于配置文件目录：

```json
{
  "schemaVersion": "M9.1",
  "goldDecisionsFile": "m8-input-decisions.json",
  "outputDecisionsFile": "m8-output-decisions.json",
  "supplementalDecisionsFile": "m9-supplemental-decisions.json",
  "signedSourceFiles": ["actual-a-signed-source.pdf", "actual-b-signed-source.pdf"]
}
```

各decisions文件是决定数组；`signedSourceFiles`应包含所有被使用决定需要的来源（示例两个路径仅说明格式）。没有实际来源时省略配置，保留待审输出。正式M9质量还要求M8原正式门禁：真实API、FINAL_EVALUATION、非作者暂定集、已审核BLIND，外加M9补充来源链；Mock/DEV补充审核也不能变成正式结果。
