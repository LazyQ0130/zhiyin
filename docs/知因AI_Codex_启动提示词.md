# 知因 AI｜交给 Codex 的启动提示词

你现在负责从零（或在我指定的已有代码仓库上）开发一款面向学生的「知因 AI」学习诊断 Web 产品。

## 必读与权威顺序

1. **首先完整阅读** `docs/知因AI_完整产品开发文档_PRD_v1.0.md`。
2. 依次查看 `references/zhiyin_ui_six_pages.png` 六页总览、六张单页 PNG、`references/zhiyin_ui_six_pages.html` 设计稿（静态视觉参考，不是可以直接照搬的业务实现）。
3. 查阅 `tests/诊断评测_种子案例.json`：仅是工程测试样例，尚非经过教师标注的正式准确率 Gold Set。
4. 规范冲突时：**PRD 业务规则 > 已确认六页信息架构 > UI 视觉参考 > 你自己的默认选择**。请不要擅自新增一级导航。

## 当前任务

按 PRD 第 14 节的 M0 → M5 里程碑实际动工，尽量在可用工具和环境内持续推进，而不是写一份计划就停下。每个里程碑完成后运行测试、总结结果；未经实际验证不能宣称通过。

**首要目标**：优先实现贯通的最小纵向闭环——登录、输入/上传题目、确认识别内容、写步骤、AI 追问、结构化错因报告、针对性训练、保存档案，然后优化全部六页。

## 明确禁止

- 禁止只做 Demo 首页、静态六页壳、只会回答问题的聊天机器人。
- 禁止将诊断结果统一写为“已掌握”，或伪造学习分数、误把模型假设当事实。
- 禁止在浏览器暴露任何模型 API Key；禁止使用真实 Key 编写截图或测试 fixtures。
- 禁止依赖真实付费模型才能本地验收；同时也禁止把 Mock 当真实诊断上线。
- 禁止擅自增加“错题本、知识图谱、计划、学习资源”等新的一级菜单。
- 禁止为追求动画牺牲中文输入法、消息滚动、阅读和可访问性。
- 禁止绕过未成年人保护与注册准入规则直接公开发布。

## 开始前先做 5 件事

1. 检查工作目录与 Git 状态，是否已有代码；不得破坏已有文件。
2. 确认正在使用的 Node.js、Next.js、Prisma、Tailwind 等 API 与官方当前文档兼容，选择稳定组合并锁定。
3. 建立 `docs/ADR/` 和 `docs/reports/`，写下必要工程取舍（不能违背 PRD）。
4. 按 PRD 先实现 MockGateway 可用的完整测试链路，同时留好真实阿里云百炼网关；无密钥时明确展示演示标签。
5. 产出 M0 最小可运行系统，立即运行 typecheck、lint、build、基本端到端烟雾测试。

## 技术与 UI 重点

- 六页一级导航：**首页、开始诊断、学习诊断、针对训练、学习档案、我的**。
- Next.js App Router + TypeScript strict + Tailwind/shadcn/ui + PostgreSQL/Prisma + Zod，模型通过服务器 ModelGateway，默认优先阿里云百炼 `qwen3.8-flash`。
- 学习诊断页桌面双栏：左题目与真实步骤，右 AI 对话/追问；手机端使用题目/对话切换。
- 先追问再提示；有证据才确认错因；报告区分“初步判断/有证据支持/经验证/待确认”；训练的单次做对不能推出长期掌握。
- 图片 OCR 仅填充可编辑内容，学生明确确认后才开始正式诊断。
- 中文 IME 回车防误发；距底部 80px 内自动跟随新消息、上翻停止；浅色优先、暗色完整、等宽数字、动效克制。
- 测试必须包含跨用户越权、重复提交、模型超时、非法 JSON、隐藏标准答案、提示使用后不判独立等高风险分支。

## 每阶段输出格式（不要省略）

1. 本阶段目标与完成情况。
2. 实际新增/修改的文件、路由、迁移和代码结构。
3. 运行命令及真实输出摘要，失败项与原因。
4. 最小用户路径是否亲自执行，UI 截图或自动化证据。
5. 安全、模型、合规限制是否有缺口；哪些测试未做。
6. 下一阶段待办与按优先级排列的问题。

**现在开始：先审查工作区和文档，执行 M0；如环境允许，完成 M0 后直接推进 M1/M2 的最小贯通闭环。不要停留在计划。**
